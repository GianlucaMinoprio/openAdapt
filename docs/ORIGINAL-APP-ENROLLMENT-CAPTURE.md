## Purpose and limits

Record first-time Bluetooth pairing and Nike application enrollment, including physical-confirmation events, public-key exchange, authentication and a subsequent ordinary reconnect. Earlier recordings only establish successful original-app existing-key authentication. Discovery alone is already demonstrated.

Nike's [troubleshooting guide](https://www.nike.com/help/a/adapt-troubleshooting) distinguishes a pairing-clearing **system reset** from power cycling and the 15-second hardware reset. The documented app procedure is Settings → Reset Shoes → confirm Reset Shoes, followed by forgetting each affected shoe in phone Bluetooth settings. The physical-button procedure is an alternative, not an additional step. The guide calls for resetting both shoes.

This removes the working pairing and requires customization again. Existing private captures, backup and saved keys preserve evidence, but cannot guarantee restoration after the shoes change keys. Successful setup with today's installed app is unproven; Nike's [retirement notice](https://www.nike.com/help/a/adapt-app) does not guarantee a new enrollment. A passive public-key exchange capture is not itself recovery of the newly derived application secret.
